Capacity tab: review, flow and four directions

The Capacity tab answers one question for a board: over the next weeks, do we have enough people for what the hosts need? Today it shows the parts of that answer in four separate places. This page reviews the tab as it ships, walks through how planners and managers use it, proposes a shorter flow, and shows four redesign directions as working mockups you can click and type into.

2 · Flow today

How people use it now

Two jobs use this tab. Planners (engineers) enter how many people each host needs. Managers and viewers read it to see whether the board can cover that. Red steps are where the tab slows them down.

Planner: fill next weeks' demand

  1. Open Capacity. It shows the last board looked at.
  2. Pick the board and the range (1–8 weeks).
  3. Press Start from confirmed plan, read the confirm dialog, accept. Empty cells fill with the latest confirmed day.
  4. Adjust the hosts they look after: type, Enter, right-click to fill the week, Ctrl+C / Ctrl+V.The tricks are only explained in the footer paragraph (F10).
  5. Scroll up past the chart to see whether the change fixed the gap.The gap and the inputs are never on screen together on a long host list (F4).
  6. Press Copy this week → next week.Always copies the current week. To fill week 3 they copy by hand.
  7. Export (Excel / JPG / PDF) and send it on.
  8. When the cycle ends, press Reset to 0 for the next planner.Irreversible, and it sits beside the everyday buttons (F6).

Manager or viewer: are we covered?

  1. Open Capacity, pick a board.
  2. Read the stats row: short days, biggest gap, peak.
  3. Scan the chart for problem days.A 1-person and a 6-person shortfall look almost the same (F1, F3).
  4. Hover each bar to find out why: leave, on-call, named.Mouse only. On a phone or with a keyboard there is no way to see it (F5).
  5. Switch to the other board to see if it has people to spare that day.Only one board at a time, and the switch doesn't say which board has a problem (F11).
  6. Decide what to do somewhere else: call on-call staff, move people, ask a host.The tab stops at the number. Nothing points to the next step.
3 · Proposed flow

Read, explain, plan, hand over

The same jobs in four stages. Each stage happens in one place on screen, and moving to the next stage is one click.

Read

One line says how many days are short and which day is worst. The days are sorted by severity, not only by date.

  • Gap drawn around a zero line, so −6 looks 6× bigger than −1
  • Board switch shows a red count of short days per board
Explain

Click a day to see why: demand per host, available people minus leave, on-call free, people named so far.

  • A panel or popover replaces the hover tooltip
  • Works with touch and keyboard
  • Shows spare people on other boards that day
Plan

Edit the host rows while Demand, Available and Gap stay pinned above them and update as you type.

  • "Fill from confirmed plan" is the main button
  • Copy week asks which week to which
  • Add a host as the last row of the grid
Hand over

Export, then clear the board for the next planner, with the risky step kept out of the main row.

  • Reset to 0 lives in a ⋯ menu, styled as destructive
  • Its dialog offers "Export first"
Summary before detailThe answer sits above the chart, and the chart above the grid.
Gap next to the inputEvery edit shows its effect without scrolling.
Why takes one click, not a hoverThe breakdown can be clicked or tapped, works with a keyboard and can be read aloud.
Risky actions are out of the waySame rule as the board toolbar's tidied row 1.
Phone reads, desktop editsOn a phone, a list of days instead of a 10-column grid.
4 · Directions

ARefined grid

Keeps today's layout and fixes it. The 230 px chart becomes a 74 px gap strip drawn around zero. Demand, Available and Gap rows are pinned above the host rows. The toolbar has one main button and a ⋯ menu. Click an Available number for the breakdown. Try it: change a number in a host row and watch the Gap row.

Desktop · 1240 px

Gains

  • Gap visible while editing (fixes F4)
  • Severity drawn to scale (F1, F3)
  • Click instead of hover for why (F5)
  • Calmer toolbar, Reset tucked away (F6)

Costs

  • Still one board at a time
  • Explains why, but doesn't suggest what to do
  • Loses the "available as a bar" picture planners know

Build

  • Small: same capacityModel, new rows in renderCapacity
  • Excel export unchanged
  • Existing Capacity e2e checks need selector updates

BAnswer first: gap timeline and day panel

Built for the reader. A sentence states the answer, a large gap timeline shows every day around zero, and clicking a day opens a side panel with why and what you could do (on-call, the other board, the hosts that drive the demand). The host grid moves to a second tab, open by default for planners. Try it: click a day.

Desktop · 1240 px

Gains

  • Fastest answer for managers
  • The tab suggests a next step for the first time
  • Phone gets a real layout: list of days and a bottom sheet

Costs

  • Planners switch between the timeline and the grid tab
  • "Spare on Board Two" needs the other board's numbers loaded

Build

  • Medium: new panel; the arithmetic already exists in Capacity.aggregate
  • Suggestions are read-only links, no new writes

CAll boards heatmap

Built for the manager. Rows are boards and columns are days. Each cell is the gap, coloured and marked by severity, with a total row for all boards. Expand a board to edit its host rows in place. A banner points out days where one board is short and another has spare people. Try it: expand a board, or click a cell.

Desktop · 1240 px

Gains

  • Ends "one board at a time" (F11)
  • Shows when people could move between boards
  • Fits 3–6 boards and 8 weeks on one screen

Costs

  • Changes the tab's model, which existing users know
  • Editing inside expanded rows is denser
  • Roles that see one board get a one-row heatmap

Build

  • Large: load demand and inputs for every board, plus a new layout
  • Capacity.aggregate already accepts several boards

DGuided planner

Built for the editing job. A step rail on the left shows the cycle: start from the confirmed plan, check each host, review the short days, share, and hand over. The grid marks cells changed since the start and records who checked each host. On a phone, one host at a time with +/− steppers. Try it: tick hosts as checked, or edit a cell.

Desktop · 1240 px

Gains

  • New planners see the whole cycle
  • Several engineers can split hosts and see progress
  • Phone editing becomes realistic

Costs

  • The rail takes 250 px from the grid
  • "Checked by" needs a new stored field per host row
  • Steps can feel slow to experienced planners

Build

  • Medium to large: schema change for checked and changed markers
  • The step rail itself is plain UI

6 · Recommendation

Ship A, add B's day panel, keep C for later

A + B combined fixes every High finding for the least code and keeps what planners already know.

  1. Now (A): gap strip in place of the bar chart, pinned Demand / Available / Gap rows, one Confirmed | Forecast band, toolbar with "Fill from confirmed plan" as the main button and Reset in a ⋯ menu, "+ Add host" as the last grid row, a ⋯ menu on each row instead of the ✕, and short-day badges on the board switch.
  2. Next (from B): clicking a day or an Available number opens the day panel (why plus suggestions) on desktop and a bottom sheet on a phone. The phone layout becomes the day list.
  3. Later (C): an "All boards" choice in the board switch, if managers ask for it. The aggregation already supports it.
  4. Take from D now: green marks on cells changed since "Fill from confirmed plan", and a "Copy week…" dialog that asks which week to which.
