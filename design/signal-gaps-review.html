Signal: what still needs updating

I opened every tab, dialog, menu, popover and toast in the real app, at desktop width (1400px) and phone width (390px), using the test harness's sample data. I compared each one with the Signal direction (design/signal-proposal.html): three surfaces (a side inspector for one record, a workbench for many items, a small dialog for one decision), navy as the only action colour, Geist type with mono for numbers, 8/12px corners, and structure from space rather than a box around everything.

Most of the app already follows Signal. Below are the 21 places that don't yet. Each one shows today's screenshot and how it would look after the update. The Settings screens on phone aren't in this list; they're in the separate PR #73.

Long help text in the record panels

Low

Host name, Google Maps link, Bulk edit and the export panels each carry a 3–5 line paragraph under a field (see the screenshots in items 03, 07 and 15). After: one line under the field. The rest moves behind a "How this works" link that opens inline, so forms stay short enough to scan.

21

"Close" styled as the primary action

Low

The read-only dialogs (Forecast, Holds taken, Merge decisions, Temporary password's Done is fine) end on a filled navy Close. Signal keeps one filled button per surface for an action that changes something. Close becomes a plain button. This is the rule behind item 14, applied everywhere.
