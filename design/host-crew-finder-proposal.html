Find crew by host history

Where the lookup should live, how it works, nine more helpers for assigning people, and the Missions tiles counting this year only. Every name, host and number in the mockups is invented sample data.

Short answer

  1. The Host tab is the home of the lookup. Search a host, open it, and a new People view lists everyone who has worked there with their days, their last day, and whether they are free on the day you are planning.
  2. The Board gets a shortcut to the same list, because that is where the assigning happens: Find crew on a mission sorts the available-people panel by days at that mission's host.
  3. No new data is needed. The app already stores one row per person per day per host (the Host Record) and already counts the days. The work is showing it at the right moment.

Review

What the app has today

The day counts exist

Host tab › Skills matrix › open a host: the names, their days, their last day, and experienced at 5 days (Settings › Host experience).

Host search exists

The Host tab's search box already finds a host by name, location, service area or a person's name.

A person's side exists

The Employee profile lists the hosts one person has worked, with days. Review & merge shows days at the host for each person.
  • 1It is three steps away from the work. Host tab, switch to Skills matrix, expand the row. On the Board, where an engineer assigns, there is nothing about who knows the host.
  • 2It does not say who is free. The list names 22 people. The engineer needs the few who are on Standby or on-call and free on the planning day.
  • 3It cannot act. From the list there is no way to put a person on a mission. The engineer has to remember the names and go back to the Board.
  • 4Clicking a host opens the edit form. Name, location, area and note. A role that cannot edit hosts gets a message and no record to read.

H1 · Host tab

Open a host and see who has worked there

A click on a host opens a read-first record, the same panel the Employee and Mission records use, with a People view. Edit stays one button away. Try it: search, pick a host, switch the chips.

H1 and H2

How it is built

  1. Data: none new. Days per person per host and the last day come from the Host Record (deployment_history), which the Host tab already loads. The day's status comes from the plan on screen.
  2. One shared list drawn in two places, so the Host tab and the Board can never disagree, and the same rule as the Skills matrix decides experienced.
  3. Demo: the sample data at /?demo already has a Host Record, so both views can be previewed there before release.
  4. Order: H1 first (one PR), then H2 (one PR). Each is small enough to review on a deploy preview.

Limits to know: a forecast day does not count as a day worked until it is merged, the same as everywhere else. Days counted before a host was merged or renamed follow the host, as today.

Missions tab · built in this PR Done

The tiles count this year's missions

Before, Total and Closed counted every mission ever registered, so they would only grow. Now a mission counts when it runs in the current year.

  • The rule: every open mission counts. A closed mission counts when its last working day is in this year.
  • The new-year weeks need no special case. A mission still on its 2026 number in January is open, so it is counted, and it keeps its place under No new-year number until the Site Admin enters the 2027 number.
  • Total says its year (in 2026) and its tooltip says how many earlier missions are left out.
  • The list is unchanged. Closed and All still show earlier years' missions, so nothing is lost from search, Export or Bulk edit.

One point for you to confirm (S1 below): an open mission still on a 2026 number stays counted for as long as it is open, with no cut-off after two weeks. Dropping it on a date would hide a running job from Total while it is still on the board.
