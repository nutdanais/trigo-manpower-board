01

P0Top bar · desktopM

At any window narrower than about 1,340px the tab strip is cut off behind the status pill, with no arrow or fade to show there is more. At 1280px (a very common laptop) Capacity is hidden. At 1100px Manpower, Host and Capacity are all gone, and "Ma…" peeks out under the pill. People will think those modules were removed in this release. Measured: tabs clip at 1024, 1100, 1180 and 1280px in English and Thai; fine from 1366px. #board-tabs has overflow hidden and the status pill (#mode-pill) holds three phrases.

02

P0Buttons · everywhereS

When a navy button is disabled and the mouse is over it (or it was just tapped on a phone, where the hover state sticks), its background turns white but its label stays white, so the button looks empty. This hits about a dozen buttons: Bulk edit Apply changes, Export Export, Add Mission Add selected, Hide/Unhide Save, Settings Save, Review & merge Apply, Review changes Apply, Copy forecast, and Sign in while it is signing in. Cause: styles.css:410 .btn:disabled:hover { background: var(--panel) } applies to .btn-primary too.

Today (pointer over the disabled Apply button)

P1AccessibilityS

Pressing Tab from the top goes Lock → date → avatar → toolbar and skips Board, Overview, Org Chart, Manpower, Host and Capacity. They are plain <div>s with a click handler, so keyboard and screen-reader users can't switch modules. Employee cards on the board are <div>s too.

Today

// app.js renderTabs()
const ov = document.createElement("div");
ov.className = "board-tab tab-overview";
ov.onclick = () => { … };

Proposed

// one helper for all six tabs
const ov = document.createElement("button");
ov.type = "button";
ov.className = "board-tab tab-overview";
ov.setAttribute("aria-current", isOverview() ? "page" : "false");
ov.onclick = () => { … };

Reset the button styles in .board-tab (border, background and font: inherit). Give the focus ring white on the navy bar.
